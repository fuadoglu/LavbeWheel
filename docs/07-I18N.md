# 🌍 Localization and language selection

## Registry and launch scope

[locales.json](../config/locales.json) lists 110 planned BCP 47 locale identifiers, native labels and direction. Registry status is planned, not translated. Launch requires every record to reach reviewed status with UI, accessibility, metadata, legal text and 300 reviewed localized game cards. Content-specific culturally adapted replacements are allowed. English fallback is a resilience mechanism, never a way to pass translation completeness gates.

## Negotiation

Global priority: explicit locally saved preference → language in opened link → ordered navigator.languages/Accept-Language match → coarse country hint → en. However, a language-specific public URL always keeps its URL/content/canonical language; a different saved preference produces a suggestion rather than an automatic redirect. Shared non-indexed shells may apply saved preference directly. On /, render a useful x-default page and choose matching app UI locally without redirecting crawlers; present a real link to the selected locale route.

Match exact locale first, then approved aliases and base-language fallback. zh-Hans/zh-Hant use explicit mapping, not a blind two-letter cut. Country hint is optional and cannot override device or explicit choice. No GPS request, IP retention or third-party geolocation call; if a trusted CDN country header exists, consume only the country code. Unknown signal falls back safely. Never equate country with language. Language picker uses native names, search and recent choice, not flags.

## Translation pipeline

Stable semantic keys with ICU-style plural/select messages. No concatenated translated sentences. Separate UI catalog, SEO catalog, pack localization and legal versions. Missing keys, wrong placeholders, invalid plural rules and unescaped markup fail validation. Translation imports are previewed with diff and source version, then reviewed; source changes mark dependent strings stale. Content publication is versioned and reversible.

Every locale has reviewer, reviewedAt, sourceHash and coverage metadata. Machine assistance is allowed only as draft content; no external translation API is required by this project. Do not fabricate review records. UI, rules and consent must remain understandable. Legal translations require operator-approved review. This work is a substantial content deliverable, not solved by locale metadata.

## Layout and formatting

Use CSS logical properties and dir on root; isolate names with bdi. Keep physical clockwise rotation and pointer semantics consistent rather than mirroring chance calculations. Format dates/numbers using Intl with UTC stored timestamps. Segment text by graphemes with Intl.Segmenter or a bundled tested fallback; implement the same Unicode segmentation rules server-side. Normalize NFC without merging distinct entries. Reject unsafe controls while allowing ordinary RTL text and valid ZWJ emoji sequences.

Self-host only necessary locale font subsets, test shaping and diacritics, then remeasure canvas when fonts load. No initial loading of 110 dictionaries/fonts. Service worker caches chosen catalogs/pack versions only. Language change preserves session and card IDs, not a new random draw.

## Evidence

Automated screenshot matrix for 110 locales in both themes; manual deep checks for en/az/tr/ru/ar/he/fa/zh-Hans/ja/hi and representative long-string locales. Review native wording in all 110; layout automation is not linguistic review. Validate locale URLs and reciprocal hreflang only for published equivalents.
